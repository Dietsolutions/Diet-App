What has to change in the app

The approved design is a full inversion of the shipping theme: warm-dark to light, molten orange to lime, Space Grotesk and Plex Mono to Archivo and Plus Jakarta Sans. This is the audit of what that costs, and where the leverage is.

1

The good news

The app styles almost entirely through inline style={{ }} objects reading from a single exported token object, s2, in client/src/theme/tokens.ts. There is no scattered Tailwind colour usage to chase. Rewriting that one file — keeping every existing key name — flips the majority of the app in a single edit.

On top of that, three shared primitives in client/src/components/ui/ — Card.tsx, HairLabel.tsx and Pill.tsx — are used throughout. Restyling those three propagates further than any other change you can make.

2

The bad news

A key-for-key swap will break things in ways that compile cleanly and look fine in a diff. Three traps, each needing a grep pass rather than a token edit.

Trap 1 — elevation invertsSilent

In the dark theme bg is the darkest colour and surface sits above it. In the light theme the page is tinted (#F2F1EC) and cards are pure white — so the direction of "raised" flips. Any component that relied on surface being lighter than bg now reads backwards.

Trap 2 — dark text on accent fillsInvisible text

The current code writes near-black text on orange as background: s2.accent; color: s2.bg, because s2.bg was near-black. After the swap that becomes lime on near-white — unreadable. Every such pair has to become background: s2.accentFill; color: s2.ink.

grep -rn "s2\.accent" client/src --include=*.tsx -A2 -B2 | grep "s2\.bg"

Trap 3 — hardcoded Strain hexBypasses tokens

Some components skip the token object. BrowseRecipesTab.tsx:453 uses the literal '#0C0907' as text on an active pill. AuthScreen.tsx:409 hardcodes password-strength colours. And client/src/index.css pins the dark theme globally in @layer base — body background, body text, and the html font family.

grep -rn "#0C0907\|#120D0A\|#17110C\|#F5EFE8\|#FF6A2A\|#FF3E3E" client/src

The macro colours need two variants

Retuned for light backgrounds, the macro fills (#6FB93B, #F2B93B, #FF8A6B, #59C7B4, #63B8E8) work as blocks and bars but are too light to read as text on white. Add a darker text variant for each — proteinText, carbsText, fatText, fibreText, waterText — and use those wherever the value is a number rather than a swatch.

What to do about mono

The old design used IBM Plex Mono for every number and kicker label — roughly 400 call sites. Fresh Light has no mono face. Repoint the key to Plus Jakarta Sans so nothing breaks, then add font-variant-numeric: tabular-nums wherever numbers sit in a column, so chart axes and macro tables still align. Two files hardcode the family and need editing by hand: MonthlyCalorieChart.tsx and weight/WeightProgressChart.tsx.

What needs backend work

Four things the design shows that the current code cannot produce. Each needs a hook or endpoint change — no amount of restyling gets there.

#ScreenWhat's needed
1TrackA per-day series for each macro — { date, consumed, target }[] over a rolling window. useTracker.ts exposes only the monthly calorie aggregate. Water and adherence already have per-day data; the four macros do not.
2TrackPer-day meal counts addressable by date (eaten vs planned) for the day-detail card, plus a bulk mark all eaten mutation.
3TrackPer-day adherence % for the visible month, to tint the calendar. Derivable from existing meal logs but not aggregated or exposed.
4Monthly macrosDaily-average / days-under / days-over currently computed for calories only. The design recomputes all three per macro tab.

Land these before the Tracker restyle, or stub them behind a flag and ship the UI dark.

5

Deliberate spec changes

Places where the design intentionally departs from what the code does today. These are decisions, not drift.

  • Onboarding condenses 7 steps into 5 by grouping. No field was removed — every key in OnboardingData is still collected. Verify against types/index.ts before finishing; an earlier draft silently dropped fields.
  • Weekly budget stays out. It exists in the onboarding defaults but is never rendered as an input in the current code, so the design omits it.
  • Slide-to-continue only on the final onboarding step. Steps 1–4 use a plain tap button.
  • The medical disclaimer becomes a link on the auth screen, sitting beside Privacy Policy and Terms of Service rather than as a block of body text.
  • Long option lists are searchable — 56 countries, 57 cuisines, 14 allergens. Country and city become compact single-selects showing the chosen value, with results appearing only while typing.
  • Allergens and Foods-to-avoid get one search zone each, with the free-text "other" folded underneath as a + Not listed? input — not a second field at the bottom.
  • The product is renamed from AI-DPT to Planyourplate. Tagline under the auth lockup: "Your nutrition companion".
  • 1 glass stays 250 ml, goal stays 2.5 L. Older mocks in the design history show 300 ml / 3.0 L. The repo is right; do not follow the old mock.
