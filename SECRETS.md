# Secrets & One-Time Setup

To go from "code on GitHub" to "live in App Store and Play Store", you need
to configure a handful of secrets **once**. This doc lists every secret,
where to get it, and what to paste.

All secrets go to: **GitHub → your repo → Settings → Secrets and variables → Actions → New repository secret**

---

## Required for iOS builds

| Secret name | Where to get it | Example value |
|-------------|-----------------|---------------|
| `APPLE_TEAM_ID` | App Store Connect → Membership → Team ID | `A1B2C3D4E5` |
| `APPLE_ID` | Your Apple Developer account email | `you@yourcompany.com` |
| `APPLE_ITC_TEAM_ID` | App Store Connect → Apps → [your app] → App Information → Apple ID Team ID (often same as Team ID) | `A1B2C3D4E5` |
| `MATCH_GIT_URL` | A **private** git repo you create for storing iOS certificates. URL can be HTTPS. | `https://github.com/yourorg/ios-certs.git` |
| `MATCH_PASSWORD` | Any strong password — used to encrypt the match repo | (use `openssl rand -base64 32`) |
| `KEYCHAIN_PASSWORD` | Any strong password — the CI keychain is temporary and ephemeral | (use `openssl rand -base64 32`) |
| `APPLE_APP_PASSWORD` | appleid.apple.com → App-Specific Passwords → generate | `xxxx-xxxx-xxxx-xxxx` |
| `APP_SPECIFIC_PASSWORD` | (same as above — used by `altool` in local builds) | `xxxx-xxxx-xxxx-xxxx` |

### One-time: populate the match repo

The first time, you (or the CI) must run `match` in **write** mode to create
the certificate + provisioning profile. Run this locally:

```bash
cd ios
bundle exec fastlane match appstore \
  --app_identifier com.dietplan.tracker \
  --git_url "$MATCH_GIT_URL" \
  --team_id "$APPLE_TEAM_ID" \
  --username "$APPLE_ID" \
  --readonly false
```

This creates a CSR, sends it to Apple, downloads the cert, encrypts it with
`MATCH_PASSWORD`, and pushes to the match repo. Subsequent CI runs use
`--readonly` to fetch only.

**After this, future certs are auto-managed.** They expire after 1 year
and match will renew them automatically if you run match in write mode
periodically. Apple Push Notification certs are not in match — handle
those separately via the push provider.

## Required for Android builds

| Secret name | Where to get it | How to set |
|-------------|-----------------|------------|
| `ANDROID_KEYSTORE_BASE64` | The output of `base64 -i android/app/diet-plan-release.jks \| pbcopy` | See keystore script |
| `ANDROID_KEYSTORE_PASSWORD` | Generated by `./scripts/generate-android-keystore.sh` | paste from script output |
| `ANDROID_KEY_ALIAS` | `diet-plan-release` (default) | literal string |
| `ANDROID_KEY_PASSWORD` | Generated by `./scripts/generate-android-keystore.sh` | paste from script output |
| `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` | Play Console → Setup → API access → Create service account → download JSON | paste the **entire JSON contents** as a single line |

### One-time: create the keystore

```bash
./scripts/generate-android-keystore.sh
```

This outputs a random password. **Copy it to your password manager IMMEDIATELY.**
Then:

```bash
base64 -i android/app/diet-plan-release.jks | pbcopy
```

and paste that into the `ANDROID_KEYSTORE_BASE64` GitHub secret.

### One-time: Play App Signing

Play Console recommends **Play App Signing**: you keep one upload key (the
keystore we generated), and Play Console keeps a separate app-signing key
that end-users see. To enable:

1. Play Console → your app → **Release** → **Setup** → **App integrity**.
2. Click **Set up Play App Signing**.
3. Choose **Use Google-generated key** (easiest) **or** upload your own.
4. If uploading your own, paste the SHA-256 fingerprint from the keystore
   script output.

Once enabled, you can **lose your upload keystore** and still push updates —
Google will issue a replacement upload key. (You cannot, however, recover
the app-signing key — that would require a new app listing.)

### One-time: Play Console service account

For CI to upload AABs:

1. Play Console → **Setup** → **API access** → **Create new service account**.
2. Follow the link to Google Cloud Console.
3. Create a service account with **Service Account User** role.
4. Create a JSON key. Download it.
5. Back in Play Console, grant the service account **Release manager** permission.
6. Copy the entire JSON file contents into the `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` secret.

## Required for the web build (Vercel + Capacitor)

These are not GitHub secrets — they're Vercel environment variables.

| Variable | Where to set | Value |
|----------|--------------|-------|
| `DATABASE_URL` | Vercel → Project → Settings → Environment Variables | (Neon pooled connection string) |
| `DIRECT_URL` | Vercel | (Neon direct connection string — for Prisma Migrate) |
| `JWT_SECRET` | Vercel | (any long random string) |
| `ANTHROPIC_API_KEY` | Vercel | (Claude API key) |
| `VITE_API_URL` | Vercel | `https://api.dietplan.app` (the public API URL) |

For Capacitor (the native apps), set `VITE_API_URL` as a GitHub secret
**at build time** so the JS bundle in the .ipa/.aab hits your production API.

## Verification

After setting all secrets, test the pipeline:

1. **Trigger iOS build manually**:
   - GitHub → Actions → "Build iOS" → Run workflow → build_mode=release, upload_testflight=false
   - Wait ~5-10 min. Check the .ipa artifact is downloadable.

2. **Trigger Android build manually**:
   - GitHub → Actions → "Build Android" → Run workflow → build_mode=release, upload_play_console=false
   - Wait ~3-5 min. Check the .aab artifact is downloadable.

3. **Push a tag** to test the full release path:
   ```bash
   git tag v1.0.0
   git push origin v1.0.0
   ```
   Both workflows fire. With `upload_*=true` inputs, both uploads happen
   automatically.
